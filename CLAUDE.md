# slapmini – project facts

A compressed, top-down 2.5D browser version of Slapshot: Rebound (WASD to move, the mouse angle rotates the stick around the player),
built to train RL bots. The physics must eventually match the real game. Ian is recording practice-mode clips for calibration.

## Architecture
- Cargo workspace with `sim`, `calib`, `sim-wasm`, `bots` and `sim-ffi` (see "Bots and training"), plus `train/` (Python PPO), plus `web/` (the feel lab: Vite + TypeScript, no framework) and `measure/` (Python: real clips → trajectory CSVs). Commands are in README.md.
- **sim** (pure, deterministic): `step(&mut State, &[PlayerInput], &Params)`. No I/O, no clock, no RNG. Trig goes through `libm`, so native and wasm give identical bits.
  Deps: serde, serde_json, libm. `params.json` is embedded with `include_str!` as `Params::default()`.
  - `State { tick, puck: Puck{x,y,z,vx,vy,vz,in_net}, players: Vec<Player>, score }`. The player count is not hardcoded (`State::new_default(p, n)`, tested with 6).
  - `Player { team, x, y, vx, vy, facing, stick_angle, stick_omega, dash_timer, dash_cooldown, dash_prev }`.
  - `PlayerInput { move_x, move_y, stick_target_angle (world rad), dash, lift }`.
  - Each step: controls update once, then `substeps` collision substeps (players → board → player-player → puck integrate → body/stick → nets → boards), then goal detection.
  - Rink: a rounded rectangle centered at the origin. Nets are 3 static segments each (sides + back) at ±`net_x`, mouths facing center. A puck in net 0 (+x) scores for team 0.
  - Stick: a rod pivoting at the player center, I = m L²/3. The angle chases the target with a braking bang-bang profile (max ang speed + accel). The impulse uses stick-head velocity (v_player + ω×r) and feeds back into ω. It only collides when `stick_z_min ≤ z ≤ stick_z_max`.
  - Speed caps after a stick hit: air / ice-normal / ice-dash, kept separate.
  - `State::to_bytes()` / `hash()` (FNV-1a) are for determinism checks.
- **params**: a flat `Params` struct generated by a macro. `get/set` by name for the fitter, and `ParamFile` keeps provenance/unit/note.
- **calib**: library + CLI (`eval`, `fit`, `synth`, `replay`). It replays a scenario, interpolates the sim at the CSV times, and reports pos RMSE (3D, m), speed RMSE (finite differences, m/s) and an optional stick RMSE.
  The fitter is Nelder-Mead in start-value-scaled coordinates. Default objective (`--objective time`) = Σ pos_rmse² + 0.1·speed_rmse².
  `--objective path` (timing-robust) = Σ path_rmse² + 0.01·v2_rmse²: both paths are smoothed identically (local quadratic fits, ±5 samples;
  the sim is first sampled at the measured times) and compared at equal distance travelled, by position and by v² (v² falls linearly
  with distance under constant friction). Frame times never align the two paths, so capture jitter and dropped/duplicated frames are
  only zero-mean noise. `eval` prints both sets of metrics. Fitted names get provenance `fitted` in the output file.
  Synthetic self-check data (generated from the sim itself) is in `calib/data/`, made with the PINNED `calib/data/params.synthetic.json`
  (the original all-placeholder params, old 60×26 m rink); `calib/tests/fit_recovery.rs` uses that file, so params.json edits don't move it.
  Real measured segments are in `calib/data/real/` (see "Segment manifest").
- **sim-wasm**: a `Sim` class with `new(params_json, n_players)`, `step(inputs_json)`, `get_state()`, `set_state(json)`, `set_params(json)`, `get_params()`, `reset(scenario_json)` (loads `initial_state`) and `state_hash()`. JSON crosses the boundary in the same shapes as params.json and scenario files.
- **web/** feel lab. `npm run wasm` builds sim-wasm into `web/wasm-pkg/` (gitignored). `npm run dev` serves it, and `npm run build` (wasm + tsc + vite) writes a static `web/dist/` with relative paths. `npm run verify` is the Playwright check.
  - The app imports the repo-root `params.json` directly, so param edits show up without a wasm rebuild.
  - `src/lab.ts`: sim owner with no DOM. Covers stepping, record/replay and practice tools.
  - `src/loop.ts`: fixed-step accumulator, capped at 5 steps per advance; the overflow is dropped and counted. It doesn't render, so it can run headless.
  - `src/render.ts`: pure drawing. `src/panel.ts`: param inputs. `src/main.ts`: wiring, plus the only wall-clock reads (`performance.now`).
  - `src/bindings.ts`: every key binding in one file.
  - Rendering: rink from params (blue lines, faceoff spots and the speed scale are DISPLAY ONLY params).
    The puck goes blue → red as z goes from 0 to 2 m, and its shadow grows and offsets with z. The puck is drawn at a 6 px minimum radius (display only).
    The stick is drawn at its actual angle, with a faint dashed line at the target angle.
    "Game view" checkbox (or `?view=game`) rotates the display like the real camera: +x up (net 0 at the top), +y left. WASD stays screen-relative.
    The ghost path breaks at time gaps and at jumps faster than 3× the largest speed cap (teleports in measured tracks).
  - Record: snapshots `initial_state` and logs an input event whenever a player's input changes. Samples t,x,y,z,stick_angle each step in the calib CSV format.
    Replay: `reset(scenario)` and then feeds the events. Keyboard and mouse are ignored during replay.
  - Practice tools change the state only in play mode; they are disabled while recording or replaying, so recordings stay pure input streams.
  - Ghost: loads a CSV, draws its path faded, and the scrub slider moves a marker along it.

- **measure/** (Python 3, numpy/scipy/opencv-python-headless, venv in `.venv/`, gitignored): `python -m measure {map,track,qa,synth}`.
  Outputs in `measure/results/` (committed: map/track JSON, traj CSV, QA PNGs). Cached median frames go to `clips/NAME.bg.png`.
  - `map`: median of 61 frames → inner board outline (the ice region enclosed by the light-grey boards and their yellow inner strip),
    straight-side extents, corner radius (from the area deficit), center line (saturation peak), center dot (the dark-ring brightness dip pair
    on the center line). Shape block: ellipse fits to the center + 4 faceoff circles (ray sampling, outlier rejection), grey lines (goal/blue
    lines), net roofs. Camera: 4 faceoff-dot patches (81×81, painted on the ice) matched once per second; raw drift = median shift, residual =
    what remains after undoing it by a translation. The map fails only if > 10% of samples can't be corrected to ≤ 2 px.
  - `track`: green HSV blobs inside the rink outline (+8 px), minus the net roofs (a large textured patch near each end, found from the median
    frame). Blobs that are green in the median frame are tagged static and may only extend an existing track at its prediction.
    Greedy linking with a gate of `2 × max speed cap / fps / m_per_px` (≈23 px/frame). Across gaps the allowance grows only with the
    track's own speed, so teleports start a new segment. Only segments that travel (≥12 px extent, ≥5 moving frames) count as the puck.
    Duplicated capture frames are dropped (compared with the previous KEPT row, so runs of repeats go too); gaps of ≤6 frames inside a
    segment are interpolated. **Camera correction**: every frame's translation is measured from the faceoff landmarks and undone
    (subpixel warp) before detection; every 10th corrected frame is re-measured (residual); frames that still exceed 2 px are dropped
    together with the stretch between them. Rows store the frame's shift and the blob area. `--no-camera-correction` = old behaviour.
    (Board-corner landmarks were tried first: the boards stand above the ice and their parallax left ~1.3 px when the camera panned.)
  - `scale`: board-based vs ice-plane scale per clip (both stored in the map JSON, `extra.scales`). `reproject`: puck blob
    centroids → ground points (`ug_px`/`vg_px` in track.json; the CSV uses them); `track` runs it automatically.
  - `segment`: free-puck stretches → `calib/data/real/` scenario + CSV pairs and `manifest.json` (see "Segment manifest").
    `segqa`: per-clip segment sheets and frame strips. `estimate`: scale-free physics → `calib/data/real/estimates.json`.
    `params`: writes the measured rink shape + markings into params.json (provenance `measured-shape`).
    `holdout`: clip-held-out fits → `params.fitted.json` + `calib/data/real/holdout.json` (needs `cargo build --release -p calib`).
    `dragmodel`: held-out drag-law comparison + smoothing/synthetic checks → `calib/data/real/dragmodel.json`.
    `compare SEG --params A --params B`: overlay of a real segment and sim replays (path + timing dots + v vs s) → `qa/compare_SEG.png`.
  - Tests: `python -m unittest discover -s measure/tests -t .` (15 tests: synthetic video with a camera pan, faceoff circles and all
    distractors → map, track, segment; geometry round-trips; circle roundness incl. a squashed circle; no real clips needed).

## Coordinate convention (all measure/ outputs; matches the sim)
- Meters. Origin = the center dot (center ice). +x along the rink's long axis, toward the net at the TOP of the game screen.
  +y such that x then y turns counterclockwise as seen on screen, i.e. +y = screen LEFT. This is the sim's frame
  (+x = net 0, team 0 attacks +x); the lab's default view is this rotated 90° clockwise, and its game view shows it as the game does.
- Pixel mapping: x = m_per_px · (v0 − v), y = m_per_px · (u0 − u), with (u0, v0) the center dot and v pointing down.
- **Scale is UNMEASURED**: m_per_px = params.json `rink_length` (60 m, a placeholder) / measured inner board length in pixels.
  Every output records this as `scale_source`. Lengths along x are right by construction; nothing about the real size is known.
- **Ice-plane scale** (`measure scale`): the board outline we measure is at ice level, not the board top. In the panned clip an
  elevated outline would widen the far-side gap between board edge and faceoff dots; measured k_board = −0.0024 ± 0.0014 (not
  significant, unphysical sign), and board length / faceoff spacing agrees across clips to 0.11% (1.8386–1.8406). So
  m_per_px_ice = m_per_px_board (both stored, `extra.scales`; `m_per_px` = the ice-plane one).
- **Puck ground position** (`reproject`): the blob centroid sits above the ice (top face + visible side wall), displaced outward
  from the principal point (image center) by k_top/2·r, k_top = (area slope)/(blob diameter) = 0.0104 / 0.0106 (puck / wall clip),
  0.0082 (lifted). Ground = pp + (c − pp)/(1 + k_top/2): up to 2.7 px (≈0.5% radial). Applied only if the blob grows ≥ 25% across
  the radii seen. Check: at bounces the ground center is 3.0–4.8 px from the board (puck radius 3.76 px), the raw blob was as close
  as 0.5 px. Effect on speeds: −0.5% (v0 −0.31…−0.59%, mean path speed −0.40%).
- t = frame_index / fps from the clip's first frame. z is always 0 (a top-down view cannot see height).

## Board friction model (session 6: not adopted)
- Question: does the real puck lose extra speed sliding along / riding the boards that the per-contact model (restitution +
  proportional tangential loss) can't give? Candidate: Coulomb-style loss, tangential speed −= μ_c (1 + e) |v_n| per contact
  (total loss ∝ how much the board turns the puck). `python -m measure boardmodel` on 9 board-contact segments, held out by clip
  (needs `docs/experiments/board_coulomb_friction.patch`, not in the sim).
- With the corrected initial speeds (`calib/data/real/boardmodel.json`), held-out score wall→puck / puck→wall:
  defaults 2.02 / 0.55; current model refit 1.94 / 0.59 (friction → 0); Coulomb 1.94 / 0.58 (μ_c 0.000 / 0.035);
  both 1.94 / 0.58; Coulomb with e fixed 2.02 / 0.61. No candidate beats the defaults in both directions; μ_c fits ≈ 0.
- Before the initial-speed fix Coulomb looked better (9.37 / 2.55 vs defaults 12.95 / 2.98) but only by lowering e to 0.28 —
  the speed-vs-geometry confound; with e fixed the models tied. The "extra loss along the boards" (puck_08) was mostly the
  noisy initial speed. **Evidence does not support a sim change**; the sim and params.rs are unchanged.

## Tracker limits (measure/)
- z is not observable. A lifted puck is drawn displaced on screen, so its x/y are wrong while airborne. The game also draws a
  ground shadow (blue dot) and a landing ring that are not used yet.
- The scale comes from a placeholder rink length, and speed caps are placeholders, so the gate and the "speed outlier" threshold are guesses.
- A puck under a net roof, under the player or merged with another green blob is missed (a gap) or biased. The puck overlapping the
  board graphics near the boards can bias the centroid by a pixel or two.
- One CSV holds many shots. Practice-tool teleports split segments (`segments` in track.json), but the CSV itself is continuous.
  Split per segment before fitting. Confidence is a heuristic (blob area vs typical, saturation).
- Puck height: blob centroids are reprojected to the ground with a per-clip parallax factor from the blob-area model
  (principal point assumed at the image center). Lifted pucks are not handled (z unknown).

## Bots and training (session s9: bots/, sim-ffi/, train/)
New crates and folders only (`sim`, `sim-wasm` and params.json were not changed by s9). 1v1, no goalie. Nothing here is frozen:
the physics is still being calibrated. Since the integration merge the sim has match rules (`State.match_state`), but the
training envs run in free play (match_state None).

### bots crate (pure Rust, deterministic, no I/O; deps sim + libm)
- **Canonical frame** (`frame.rs`): every player sees the world as if it attacks +x. Team 0 = identity; team 1 = the world
  rotated 180° ((x, y) → (−x, −y), angles + π). The rink, nets and physics are symmetric under that rotation (a rotation,
  not a mirror, so stick spin direction is preserved), so one policy plays both sides. `rotate_swap(state)` rotates the
  whole state and swaps teams, scores and the match state's team indices (tests).
- **Observation** (`obs.rs`, `OBS_DIM = 40`, `OBS_VERSION = 1`, f32, fixed normalization constants, not params-dependent):
  0–1 own x/30, y/20; 2–3 own v/14; 4–5 cos/sin facing; 6–7 cos/sin stick angle; 8 stick ω/14; 9 dash window/0.25 s;
  10 dash cooldown/1 s; 11–12 puck x/30, y/20; 13 puck z/2; 14–15 puck v/30; 16 puck vz/10; 17–18 (puck − own)/10;
  19–20 opponent x/30, y/20; 21–22 opponent v/14; 23–24 cos/sin opponent stick; 25 opponent ω/14; 26–27 (opponent − own)/10;
  28 own goals/5; 29 opponent goals/5; 30 time left/300 s (**always 0**: the envs run free play; fill it from `match_state.clock_ticks` in `observe` when training on matches);
  31 dash ready (0/1); **32–39 style slot** (`STYLE_DIM = 8`, caller-supplied, zeros by default). Angles as (cos, sin) so the
  rotation is an exact sign flip. Changing any field or constant → bump `OBS_VERSION` (checkpoints refuse to load across it).
- **Action** (`action.rs`, `ACT_DIM = 5`, canonical frame): move_x, move_y (−1..1), stick target angle (rad, canonical),
  dash (> 0.5), lift (> 0.5). `Action::to_input(team)` applies the inverse rotation → `PlayerInput`.
- **Scripted bots** (`scripted.rs`, trait `Bot`, enum `Scripted` by `Kind` id 0 chaser, 1 defender, 2 cautious, 3 idle):
  - shared `Striker`: picks a hitting spot beside the (predicted) puck, holds the stick cocked, and swings through the puck
    only when the swing will send it at the target. The shot model: the blade edge meets the puck asin(reach/r) before the
    stick points at it, the push is along the blade normal, plus `SHOT_OVERTURN` 0.054 rad, from-rest speed `SHOT_SPEED`
    18.9 m/s (both measured with `examples/shotlab.rs` on the fitted default params at the integration merge; they were
    0.041 / 19.7 on the old placeholder physics; re-measure after physics changes). The swing
    target is only 0.6 rad past the puck so the bang-bang chase brakes and the faster blade tip does not hit it twice.
    Contact is quantized by the stick's per-substep rotation (14 rad/s → 0.058 rad per substep), so a moving player sees
    ±0.06 rad shot noise.
  - chaser: striker toward the opponent net, aiming at the net center or the post side the opponent's body does not block.
  - defender: guards the own net→puck line (0.4 × distance, 2–9 m out) with the stick across the line, steps onto a shot's
    path; clears (skates through the puck toward the boards) only if it wins the race and the puck is within 11 m of its goal line.
  - cautious: waits at x = −15 m (canonical) on the puck→own-net line, engages only when the puck comes within 6 m, lets go past 9 m.
- `game.rs`: `faceoff`, `play`, `play_with_faceoffs` (scripted matches, used by tests/examples).
- Examples: `tournament` (round robin), `shotlab` (shot accuracy), `trace` (debug print of one game).

### sim-ffi crate (cdylib + rlib; deps sim, bots, serde, rayon)
- `Batch` of N envs (`env.rs`); each env: State, SplitMix64 RNG (seed ^ index-mix; used only at resets), learner slot,
  opponent (scripted or external), reward weights, style. Envs are stepped with rayon (`par_iter_mut` over disjoint output
  chunks; sequential if `threads = 1` or < 4 envs); results do not depend on the thread count (checked).
- Episode: faceoff with jitter (puck ±jitter_puck, players ±jitter_player per axis), learner team random per episode
  (`learner_team: -1`) or fixed. Ends on a goal (either side) or `max_steps` sim steps; auto-reset, the returned obs is the new
  episode's first. Time-limit ends are reported as done (PPO treats them as terminal; no bootstrapping).
- **Config JSON** (all optional): `max_steps` 3600 (30 s), `action_repeat` 4 (30 decisions/s), `learner_team` −1,
  `jitter_puck` 1.5, `jitter_player` 1.0, `opponent` "chaser"|"defender"|"cautious"|"idle"|"external", `reward` {weights},
  `style` [floats], `threads` 0 (rayon default). Unknown keys are rejected.
- **C ABI** (`lib.rs`): `slap_batch_new(params_json, config_json, n, seed)`, `slap_batch_free`, `slap_batch_reset(obs, opp_obs)`,
  `slap_batch_step(actions, opp_actions, obs, opp_obs, rewards, dones, info)`, `slap_batch_set_opponent(env|u32::MAX, kind)`,
  `slap_batch_set_style`, `slap_batch_set_reward_weights`, `slap_batch_hash` (all states + RNGs + counters),
  `slap_batch_env_hash`, `slap_batch_get_state/set_state` (State JSON), dims/version getters, `slap_last_error`.
  Buffers are caller-owned f32 (dones u8); errors return −1, panics are caught. info row (`INFO_DIM = 10`): end reason
  (0 running, 1 goal for, 2 goal against, 3 step limit), episode sim steps, episode return, learner team, raw term sums.
  `ABI_VERSION = 1`.
- The opponent observation (`opp_obs`) is the opponent's own canonical view (style zeros), so a frozen policy can drive it.

### Reward (configuration, `reward.rs`)
Raw terms measured every sim step for the learner (canonical frame), summed per decision; reward = Σ weight × raw.
| term | raw value | default weight |
|---|---|---|
| goal_for | goals scored (0/1) | 1.0 |
| goal_against | goals conceded (0/1) | −1.0 |
| puck_progress | Δ puck x / net_x (episode sum = net puck advance) | 0.2 |
| shot_on_net | 1 per learner contact (dv > 2 m/s, learner closest and within reach) leaving the puck at ≥ 5 m/s on a line into the opponent mouth; 0.5 s cooldown | 0.05 |
| possession | seconds the learner is the closest player with the puck within stick reach (+0.2 m) | 0.02 |
| defensive_position | seconds goal-side: behind the puck and ≤ 1.5 m off the own-net→puck line | 0.0 |
JSON: `{"reward": {"goal_for": 1, "goal_against": -1, ...}}` in the env config, or `--reward file.json` in the trainer, or per
env at runtime (`set_reward_weights`, a vector in TERM_NAMES order).

### Style hooks (built, unused so far)
- Every env has a style vector (8 floats) that is appended to the learner's observation (obs 32–39), and its own reward
  weights; both can be set per env at any time (`VecEnv.set_style(i, v)`, `VecEnv.set_reward_weights(i, w)`).
- **How the next session would use them** (style-conditioned policy): at every episode start, sample a weight vector per env
  around the "win" core (goal_for/goal_against fixed at ±1; shaping terms drawn from ranges, e.g. puck_progress 0–0.5,
  shot_on_net 0–0.3, possession 0–0.1, defensive_position 0–0.1, plus new terms for tricks such as lifts, dash shots, board
  passes, which need new raw terms in reward.rs), write the same vector (scaled to ~[−1, 1]) into that env's style slot, and
  train as usual (the PPO code is unchanged: the policy simply sees the style). At play time, choosing a style vector picks a
  play style; self-play opponents get random styles too. Keep the win terms dominant so every style still tries to win, and
  log win rate per style bucket. `train/ppo.py` currently sets neither (all styles 0, config weights).

### train/ (Python 3, numpy, torch; ctypes, no PyO3/maturin)
- `slapenv.py`: finds `target/release/{sim_ffi.dll|libsim_ffi.so|libsim_ffi.dylib}` (or `$SLAPMINI_FFI_LIB`), `VecEnv`
  (reset/step/set_opponent/set_style/set_reward_weights/hash/get_state/set_state), `physics_stamp(params.json)` = sha256 of the
  sorted name→value map (16 hex; notes, provenance, whitespace, CRLF don't matter).
- `ppo.py` (single file): MLP 2×256 tanh, separate value net. Heads: move 2D Gaussian (env clips), stick 2D Gaussian
  direction → atan2 → stick angle (no ±π wrap), dash and lift Bernoulli; state-independent log-std. GAE (γ 0.995, λ 0.95),
  clip 0.2, 4 epochs × 4 minibatches, 64 envs × 128 steps per update, lr 3e-4, entropy 0.003. Device auto (CUDA else CPU).
  Training starts are more spread than eval (`--jitter-puck 6 --jitter-player 2`; eval uses the env default 1.5/1.0).
  Checkpoint `runs/NAME/latest.pt`: weights, optimizer, counters, args, env config, **physics_stamp** and **obs_version**;
  resume refuses a different physics stamp unless `--allow-physics-change` (and never loads across an obs layout change).
  Self-play: `--opponents "chaser:0.2,defender:0.1,cautious:0.1,pool:0.6"`; each env draws its opponent at every episode
  start; `pool` = a frozen snapshot (policy copy) added every `--snapshot-every` updates (kept: newest 20, on disk in
  runs/NAME/pool/); up to 4 snapshots (the newest + random) are loaded at a time and act on `opp_obs` (sampled actions).
  metrics.csv per update (rolling 400 episodes: win/loss/draw, goal diff per episode, episode length, return, losses);
  `plot` → learning_curve.png. `eval` plays N episodes (equal count per env, so short episodes aren't oversampled).
- `export_onnx.py`: deterministic policy → ONNX (opset 17, TorchScript exporter): input `obs` [N, 40]; outputs `move` [N, 2]
  (clamped), `stick_dir` [N, 2] (angle = atan2), `dash_prob`, `lift_prob` [N]; sidecar `.json` (obs version, physics stamp).
  Checks onnxruntime against PyTorch on 1000 random observations. For team 1 in the browser: negate move and stick_dir.
- Tests: `python -m unittest discover -s train/tests -t .` (env determinism across thread counts, state round trip,
  reward/style config, physics stamp, short self-play run + resume + physics guard, eval, ONNX parity).

### Default choices made in s9 (all easy to change)
- 30 decisions/s (`action_repeat` 4), episodes of 30 s, end on the first goal; the learner's team is random per episode.
- Time-limit ends are treated as terminal by PPO (no value bootstrap; the env auto-resets and does not return the final obs).
- Fixed observation normalization constants (independent of params); no running obs normalization (keeps the ONNX graph
  self-contained); stick action as a 2D direction; continuous move (the real game's WASD is digital; a 9-way discrete
  move head is an option later).
- Default reward: goal ±1, puck_progress 0.2, shot_on_net 0.05, possession 0.02/s, defensive_position 0.
- Training starts are spread (puck ±6 m, players ±2 m) while eval and the env default use ±1.5 / ±1 m.
- Physics stamp = hash of param values only (display-only params included, so a marking edit also changes it).
- ONNX: deterministic policy only, opset 17, legacy TorchScript exporter (single file, no external data).
